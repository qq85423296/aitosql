## 1. 为什么（Why）

### 1.1 AS-IS（现状）

- 工作区当前只有方案与原型，无运行中的产品代码；历史方案（v2/v3、前端设计 v1）已被 SSOT v3.2 取代。
- 用户痛点（个人数据分析师/开发者视角）：手写 SQL 慢、方言差异（MySQL/Doris/ClickHouse）易错、口径靠脑子记、大表误扫无感知、查询结论无法复核。
- 既有 Text2SQL 工具的通病：执行成功即停止（"跑通了就答"）、歧义直接拒绝或乱猜、结论不可复核、无崩溃恢复。

### 1.2 TO-BE（目标行为）

- 自然语言 + 库表元数据 → 方言正确、可执行、带假设说明的 SQL；歧义不拒绝、假设先行，高风险歧义走澄清门并沉淀口径偏好（P1）。
- 复杂 SQL 是一等能力：CTE/窗口/子查询/正则全允许，不做白名单裁剪（P2）。
- "校验过了才停止"：执行后必经 `verify_result`，回退全局共享 1 次，仍不过照常交付并标注「未验证」（P6）。
- 结论可复核：复核包一键复制（问题/口径假设/SQL/执行与数据时间/行数/扫描量/风险标记）（P7）。
- 本地部署、单用户、默认 local_only 零出境；选云路由即显式出境清单（P4）。
- AI 只建议、人来裁决：注释/标准绑定/关系/指标四类建议进队列，采纳前不进提示词（P5）。

## 3. 范围（Scope）

### 3.1 本期范围内

- **查询主链路**：会话管理、SSE 流式管线（8 阶段）、生成契约、澄清门/写确认门、AST 校验、执行与元信息采集、结果校验与修正回路（≤3 轮 + 振荡检测）、追问建议、复核包、CSV 全量导出。
- **数据源治理**：在线三方言摄取（含主键/分区键/分桶键探测）、离线三通道（DDL 解析/CSV 模板/AI 草稿）、表/字段编辑、双语关系管理与 ER 图谱、字段/维度/指标标准、AI 建议队列。
- **样例库**：on/stale/off 状态治理、EXPLAIN 复验、semantic_rev 三条件缓存命中。
- **设置**：提供商与密钥管理、三路模型路由与出境清单、提示词维护与组装预览、查询与安全参数、Schema 注入参数、记忆与偏好、备份。
- **记忆与会话压缩**：流水账/总账/水位线合并、压缩前抢救、注入与容量治理。
- **工程基座**：SQLite 持久化（app.db + checkpoints.db 双库）、事件溯源（query_event）、密钥 Fernet+keyring、错误脱敏三出口、单命令启动。

### 3.2 明确非目标（Out of Scope，溯源 SSOT §17）

- 多用户、行列级权限、MCP 网关（维持暂缓）、BI 图表可视化、并行下钻编排与交叉验证、血缘分析/数据质量分。
- 指标平台（调度/报表）；样例与标准的批量导入导出（Phase 2 后再议；离线 DDL/CSV 导入不在此列）。
- 图谱自动力导向布局（手工摆位，见「待确认项」#1 的存储缺口）。
- 企业级审计、SSO、多租户。

## 4. 能力清单（Capabilities）

> 每个能力对应 spec.md 的一组功能簇；命名供下游 spec 拆分复用。

### New Capabilities

- `query-pipeline`：查询主链路（供给→生成→双门→校验→执行→结果校验→修正回路→交付），含 SSE 十六事件与幂等续播。
- `datasource-governance`：数据源注册/摄取/离线导入、表字段元数据、关系与 ER 图谱、语义层（标准/维度/指标）、AI 建议队列。
- `sample-library`：样例沉淀、stale 治理、缓存命中。
- `provider-and-routing`：提供商/密钥/三路路由/出境管控。
- `prompt-system`：系统提示词、方言能力卡、8 段信封组装与 5 步裁剪、消毒规则、组装预览。
- `memory-and-compaction`：双层记忆、水位线合并、会话滚动摘要、压缩抢救。
- `ops-and-resilience`：崩溃自动续跑、双库归属、备份/恢复、导出 TTL 治理、错误码体系。

（无——全新构建，无既有能力基线。）

## 5. 关键场景（Key Scenarios）

> 场景均可在 `prototype/*.html` 中找到对应演示落位；括号内为 SSOT 锚点。每个场景即一条端到端验收走查路径。

### S1 主链路 happy path（在线库）
用户选在线数据源提问「上个月各渠道环比？」→ supply_schema 双路 RRF 命中表 → generate 产出契约（reasoning/assumptions/SQL）→ validate（auto_limit AST 注入、R01-R14、EXPLAIN 干跑）→ execute（CONNECTION_ID 采集、30s 超时、全量 CSV 落盘）→ verify_result 全过 → done。前端：阶段卡推进、假设 chips、SQL 高亮、结果表、元信息（行数/扫描量/耗时/数据截至）、校验绿块、追问 chips。（§5、§10.3；原型 index.html 问答 1）

### S2 高风险歧义 → 澄清门
「本月收入是多少？」命中口径多版本（impact=high）→ clarify_gate interrupt → 前端选项卡（含税/不含税 + 自定义）→ 用户裁决 → `POST /queries/:id/resume`（CAS）→ 重进 generate → 裁决写入 clarify_pref 并同步直写 memory_log → 下次同类问题免问并显示「已沉淀为口径偏好」。（§5.2/§12.6；原型问答 3）

### S3 写操作确认门 + CH 只读
生成 UPDATE → R06 命中 → confirm_gate 展示风险清单 + 影响行数估算 → 用户确认才执行；取消则标注「已取消，语句未执行」。CH 数据源 `ch_readonly=true` 时红警文案明示将被服务端拒绝。（§9.4；原型问答 2）

### S4 R15 硬阻断
生成/注入多语句、INTO OUTFILE、EXPLAIN ANALYZE、CALL/DO → R15 五断言任一命中 → status=failed，交付原 SQL + 分方言文案（E3010 错误卡），不进 correct 不进任何门。（§9.1/§12.7；原型问答区新增态）

### S5 执行报错 → 修正回路 → 结果校验回退
引擎报错脱敏回喂 correct（≤3 轮，SQL 指纹振荡即终止照常交付标 failed）；执行成功但 verify 规则层不过（0 行/关键列全 NULL/行数<估计 1%）→ 消耗全局唯一回退额度重试一次，仍不过 → 照常交付并标注琥珀「未验证」。（§5.3/§9.2；原型问答 5）

### S6 崩溃自动续跑与断连恢复
进程崩溃重启：running 态 query 从 checkpoint 自动续跑至终态（前端「已自动恢复」横幅，无手动按钮）；waiting_* 门态恢复后等裁决，门不自动放行；写操作 crash 续跑重过确认门；checkpoint 缺失 → failed+标注。SSE 断连：Last-Event-ID 增量续播 / 无头全量，seq 幂等去重。（§5.4、§11.2；原型顶部横幅）

### S7 数据源注册与治理闭环
在线向导 3 步（连接→测试→摄取，测试失败红卡锁定下一步 E1001）→ 摄取计数日志（主键/分区键/分桶键）→ 表/字段行内编辑（重摄取不覆盖人工注释）→ 提示词视图与真实注入逐字一致 → 推断关系 pending 确认后才注入 → AI 建议队列批量采纳。离线库：DDL/CSV/AI 三通道，部分失败行标红，只生成不执行（执行键变「复制 SQL」）。（§7.2；原型 datasources.html）

### S8 记忆与会话压缩
澄清裁决/假设修正/存样例同步直写流水账；每查询完成异步 flush（route.ai 小模型，失败静默下轮重试）；水位线增量合并进总账（≤4000 token，超量裁最旧未命中）；会话 >40 条触发压缩，先抢救事实再滚动摘要，消息流内嵌压缩提示条；总账条目停用即时不再注入。（§12.6；原型 settings.html 记忆分组、index.html 压缩提示条）

### S9 出境管控
默认三路全本地 = local_only 零出境；任一云路由开启 → 设置页出境清单矩阵（E1-E8）逐类展示；verify_llm 在 local_only 置灰禁用，含云路由可开但 E6（结果预览前 5 行）红标。（§12.5；原型 settings.html 出境清单）

## 6. 方案分析结论

> 以下为对 SSOT v3.2 的分析结论；发现的缺口均转化为「待确认项」（§8）或 spec.md 的实现注意点，不擅自改动 SSOT 口径。

### 6.1 需求完整性：**高**

- FR/BR 自包含全集：FR-Q1~Q14、FR-D1~D13、FR-S1~S4、FR-C1~C8、BR-1~BR-16 共 65 条，每条带验收要点与原型落位/实现锚点（§7）。
- 追溯闭环：§15 需求-任务矩阵双向校验（无孤儿需求、无孤儿任务）；§13 状态清单覆盖失败/边界/空态 20 条；§4 配置默认值全表 40+ 键。
- 配套文档一致性：数据源模块配套设计与 SSOT 在实体/合并策略/AI 补全上基本一致（差异见 §8 #2/#3）。

### 6.2 方案可落地性：**高（有少量工程前提待确认）**

支撑面：
- 技术栈全部锁版本（Python 3.13 / langgraph ≥0.2 / sqlglot 30.18 实测 / React 19 / Vite 6 / fastembed+bge-small-zh-v1.5），依赖治理有收口与升级门禁（§2.1）。
- DDL 为真实可执行 SQL（migrations 0001~0004）；API 契约到字段级；SSE 十六事件完备；QueryState TypedDict 可直接编码。
- 高风险点已有实测证据：R15 五断言（sqlglot 30.18 探针复现 `SELECT 1;;SELECT 2` 等边界）；同步 IO 冻结事件循环（R7）有 anyio.to_thread + AsyncSqliteSaver 对策。
- 开发计划 4 Phase 23 任务，带依赖、验收与 golden 滚动门槛（15/30/40/50），每 Phase 留 20% 缓冲，砍项顺序明确（先 verify_llm 后 followups）。

前提与隐患（转 §8）：首次运行 embedding 模型权重下载依赖外网（#4）；T4.4「干净机器一键起」的依赖安装策略未详述（#5）；本地小模型复杂 SQL 成功率属登记风险 R1，靠 golden 基线 + 修正路由换强模型兜底。

### 6.3 前后端闭环：**完整**

- 唯一耦合面 = `/api` + SSE（D5）；前端装配五步（E5 快照 hydrate → 挂 SSE → 双模重连 → seq 幂等去重 → 横幅策略）与后端 query_event 事件溯源严格对偶（§11.2/§10.3）。
- 双门闭环：interrupt 负载 → SSE 事件 → 前端门卡 → resume CAS 裁决 → 图恢复；裁决结果既回显（E5 快照含 clarify_choice）又沉淀（clarify_pref/memory_log）。
- 配置-注入-预览同源：设置页组装预览由后端 prompts.py 生成，「与真实注入逐字一致」；表详情提示词视图同理（§10.4、FR-D8）。
- 出境矩阵联动：路由选择 → 出境清单 → verify_llm 置灰/红标，前后端共用同一份 setting（§12.5）。
- 原型即验收基准：FR 表逐条标注原型落位，T0.2 验收「视觉与原型一致」，tokens.css 唯一设计 token 来源 + stylelint 禁裸 hex（V3）。
- 四页原型核对结果：澄清门、确认门、复核包、追问 chips、未验证标注、断连/自动恢复横幅、R15 文案位、离线「复制 SQL」、分区键徽章、出境清单、预算示意均存在，与 FR 描述一致。

|---|------|------|------|---------|

### 7.3 关键数据与接口

- 业务 ID：`s_`/`q_` 前缀 + ULID（Crockford Base32，26 字符，毫秒可排序）；幂等键 `client_request_id = thread_id = query_id`。
- 数据模型 20 张表/视图（migrations 0001~0004），数据字典见 spec.md §2。
- 接口：`/api` REST 端点 30+（§10.1 总表）+ SSE 流（十六事件）+ 生成契约 JSON Schema（§6）；错误码 E1001/E1002/E2001/E2002/E3001/E3010/E4001（§18.1）。

## 9. 验收标准（可测试、可观察）

> 与 SSOT §14 任务验收一一对应；以下为需求级终验口径，开发任务级验收以 SSOT 为准。

1. **主链路**：三方言（MySQL/Doris/ClickHouse）真实库上，golden ≥50 条（含澄清门/写门/回退/0 行/R15 用例）一次通过率达到基线并记录（T4.1）。
2. **R15 硬阻断**：五断言（多语句/解析失败族/INTO 文件变体/EXPLAIN ANALYZE/CALL·DO）各有实测用例，命中即 failed + 分方言文案 + 交付原 SQL，且不进修正回路不进任何门（T1.4）。
3. **所验即所执**：确认门展示串与 execute 执行串逐字相同；auto_limit 以 AST 注入发生在 validate 内，validate 之后无任何 SQL 重写（T1.4/T1.5）。
4. **双门闭环**：写操作暂停→确认→执行、取消标注「已取消」；澄清裁决写 clarify_pref，同数据源同 term 下次免问并显示沉淀提示（T1.7）。
5. **崩溃恢复五条**（故障注入）：running 重启自动续跑至终态；waiting_* 门态恢复后可裁决且不自动放行；SSE 续播无重复无丢失（seq 单调 + 幂等）；写操作 crash 续跑重过确认门；checkpoint 缺失降级 failed+标注（T4.2）。
6. **幂等**：同一 `client_request_id` 重发返回同一 query_id 且不重复执行（T1.8）。
7. **结果校验**：规则层五检查全过才 pass；回退全局共享 1 次；仍不过照常交付并标注「未验证」琥珀块（T1.6）。
8. **出境管控**：local_only（三路全本地）下抓包零出境；verify_llm 置灰；含云路由时设置页出境清单 E1-E8 展示、E6 红标（T0.3/T1.10/T3.2）。
9. **记忆闭环**：澄清裁决 → memory_log 可见 → 合并后下次生成注入生效；40 轮会话压缩事实零丢失（golden）；总账停用条目即时不再注入（T3.5）。
10. **样例治理**：schema 变更 → 引用样例置 stale（stale_reason 记字段名）→ EXPLAIN 复验回 on；semantic_rev 三条件命中直返 SQL 并标注「复用已验证结果」（T3.1）。
11. **前端基准**：四页对照 prototype 走查通过（含 ⌘K 聚焦会话列表内过滤、>200 条虚拟滚动、ResultTable >100 行虚拟化、tokens.css 单一 token 来源）（T0.2/T1.9a-c）。
12. **性能矩阵**：有 GPU 32B FP16 首 token <3s；无 GPU ≤8B 量化 <3s；云端 <3s（网络另计）；摄取 500 表 <60s；首屏 <1.5s；execute 延迟含落盘时间单列（T4.3）。
13. **交付**：干净机器 `scripts/dev.py` 单命令启动，`/api/health` 200，前端产物内嵌（T4.4）。
14. **密钥安全**：密钥不回显、测试连接失败卡注明「密钥未外发」；keyring 不可用拒启；备份剥离密文且不含 checkpoints.db 与 exports/（T0.3/T3.2）。
