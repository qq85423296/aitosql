## 1. 目标与边界

**目标**：将数据源详情、表详情中的「AI 补全弹窗 → 完成后跳建议抽屉」改为一个连续的 AI 工作区。用户能从同一入口启动分析、查看进度、立即评审建议、离开后重新找到未处理建议。

**产品原则**：

1. 默认快速：数据源入口默认整库，本表入口默认当前表；默认建议类型 `comment/relation/std_bind`；样例值默认关闭。自选表、仅推断关系、重扫已有内容、样例值及类型选择进入「高级选项」。
2. 「生成建议」与「评审建议」是工作区的两个视图。AI 产出一律先入建议队列，**仅人工采纳后**才修改正式元数据。
3. 关闭工作区仅关闭 UI，**不取消后台任务**；「取消分析」是单独的高辨识操作。不能把中断 SSE 与取消任务混同。
4. 不添加聊天助手、不改提示词与生成算法、不更改数据库结构；优先复用现有 API 与数据模型。
5. 当前建议类型包括历史 `metric`，但生成任务的 `CompletionKind` **只有** `comment/relation/std_bind`。评审应显示既有 `metric` 建议，生成配置不能错误展示「生成指标」。

## 2. 当前实现与关键约束

- 数据源详情：`web/src/components/ds/DsDetail.tsx` 的「AI 补全 ▾」同时承载生成和查看建议；生成走 `AiCompleteModal.tsx`，完成后通过 `onReview` 打开 `SuggestionDrawer.tsx`。
- 表详情：`web/src/components/ds/TableDetail.tsx` 另有一组弹窗、抽屉及表过滤状态。统一时**两处入口都必须迁移**，不能只改数据源详情。
- 前端 API：`web/src/api/aiRuns.ts` 已有 `create/get/list/cancel/run`；`web/src/api/suggestions.ts` 已有按数据源、批次、表查询与批量采纳、忽略。类型见 `web/src/api/types.ts:152-214`。
- 后端运行中任务是按数据源互斥的：`backend/app/api/ai_runs.py:151-187`；运行中重复创建返回 409。工作区必须先识别活动任务，再允许发起新任务。
- **SSE 不是可随意重连的广播流**：`backend/app/api/ai_runs.py:224-250` 使用单个进程内队列，断开时清理队列映射；未提供逐事件重放。`aiRunsApi.run().close()` 只断流，不取消任务。离开页面后重新进入，必须以 `list/get` 返回的持久任务状态为准；不能假装重新订阅后会补齐实时事件。**第一版不改后端流机制**：已有连接保留时继续展示实时进度；连接已丢失时轮询 `get(run_id)`，展示「正在后台分析，进度可能略有延迟」。
- 前端未发现既有测试目录与依赖安装目录；不要把“代码写完”当作“验证通过”。设计约束参考根目录 `数据源模块设计.md` §4.10「AI 建议、人裁决」。

## 3. 目标交互与页面状态

### 3.1 入口

- 数据源详情页标题旁：主按钮「AI 完善数据源」；待办按钮「待评审建议 N 条」（N>0 时展示，点击直达「全部待评审」）。
- 表详情页：保留「AI 完善本表」入口，打开**相同工作区**、默认范围 `scope=table, table_id=当前表`；其「待评审」默认按当前表过滤，并提供「查看本库全部」切换。
- 标题可用「AI 完善 · 数据源名 / 表名」。关闭时保留用户所在 Tab、表和滚动位置；从其他页面回来先以服务端状态恢复。

### 3.2 工作区状态表

| 状态 | 展示 | 主要动作 |
|---|---|---|
| 无任务且无建议 | 默认范围、预计表数、将生成的建议类型 | 开始分析；展开高级选项 |
| 有历史待评审 | 待评审总数，默认显示全部待评审 | 逐项评审；可切到生成建议 |
| 创建中或运行中 | 创建中禁用二次提交；运行中显示已处理/总数、当前表、已生成数；无 SSE 时显示轮询状态 | 收起工作区；独立取消分析 |
| 完成且有新建议 | 自动切到「本批建议」，标明批次与剩余待评审数 | 采纳/修改后采纳/忽略；切换全部待评审 |
| 完成但无新建议 | 「本次没有生成新建议」，历史待办仍可达 | 调整范围重新分析 |
| 失败/取消 | 明确终态与错误，不伪装 100% 进度或成功；历史建议仍可处理 | 重新分析或查看待办 |
| 路由未配置 | 原位解释缺少 `route.ai`；允许查看历史建议 | 前往设置页；禁用「开始分析」 |

**运行中恢复规则**：打开工作区时调用 `list(datasourceId)` 找到 `queued/running` 的任务，必要时用 `get(id)` 刷新；运行阶段从服务端 `progress_done/progress_total/made/status` 绘制。由本页启动且 SSE 连接仍在的任务可叠加实时泳道；重连时不显示没有证据的历史泳道。状态轮询仅在运行中进行，终态停轮询并刷新建议列表。切换数据源必须切换对应任务、计数与筛选，防止跨源串数据。

### 3.3 评审规则

- 顶部切换「本批建议 / 全部待评审」；本批建议限定**当前运行 `run_id`**，全部待评审清除批次限制。来自表详情时默认叠加当前表过滤；选择「本库全部」才清除。
- 卡片展示：对象、当前值 → 建议值、生成依据（缺失时明确「暂无依据」）、置信度（辅助信息，不参与自动决策）；复用现有 payload 字段，不能编造现值或依据。
- 单条「采纳 / 编辑后采纳 / 忽略」；仅已被后端支持编辑的 `comment` 保留编辑后采纳，其他类型不要展示无效编辑按钮。多选后显示「采纳所选 / 忽略所选」，操作只作用于明确选中的 ID。
- 批次/表/类型过滤默认折叠；过滤变更后清除不在当前可见列表的选中项，防止批量操作波及隐藏建议。「忽略全部」不作为默认主操作；若保留，二次确认并明确影响范围。
- 采纳/忽略成功后同时更新本批、全部待办计数、表/图谱/字段等缓存；失败保留选中与编辑状态，显示错误，不产生假成功反馈。

## 4. 组件架构与文件职责

主张**单实例工作区 + 单个任务控制器**，避免两处页面各自管理同一 SSE/轮询：

1. `web/src/pages/DatasourcesPage.tsx`：持有唯一工作区打开状态和入口上下文 `{ datasourceId, tableId?, tableName?, initialView }`；提供从数据源与表详情打开工作区的回调。切换详情内部视图不销毁工作区控制器。离开路由时释放 SSE 连接但不发取消请求。
2. **新增** `web/src/components/ds/AiWorkspace.tsx`：工作区框架、两个视图、空态/加载态/失败态、任务与建议页签切换；抽屉关闭只改可见性。若组件过长，分别拆成 `AiGenerationPanel.tsx`、`AiReviewPanel.tsx`，不要把现有两个大组件机械拼进单个超长文件。
3. **新增** `web/src/components/ds/useAiCompletionRun.ts`：唯一任务控制逻辑；创建任务、保留本会话 SSE、后台轮询恢复、明确取消、终态刷新。防重复创建、过期数据源的异步回调、重复 `onEnd`（实时结束和轮询终态竞态）。`aiRunsApi.run` 无法附着已有任务，只对新建任务使用。
4. `web/src/components/ds/DsDetail.tsx`、`web/src/components/ds/TableDetail.tsx`：仅保留入口和回调，不再各自挂 `AiCompleteModal`、`SuggestionDrawer` 双层弹层。`DsDetail.tsx` 内部的 `TableDetailView` 包装组件也必须透传打开工作区的回调；已有表详情的 `scope=table`、`filterTable=table.name` 行为必须保留。
5. `web/src/components/ds/AiCompleteModal.tsx`、`web/src/components/ds/SuggestionDrawer.tsx`：尽可能提取现有生成配置/进度视图和建议卡片/变更动作到新组件；旧组件无其他调用时才删除。不要同时保留两套状态源。
6. `web/src/api/aiRuns.ts`、`web/src/api/suggestions.ts`：原则上不改后端接口契约；若需给 `run()` 增加创建中状态或防止重复完成回调，先加测试并保持 mock/真实模式一致。样式归入 `web/src/styles/app.css` 中相应数据源样式区域，避免覆盖其他页面。

**无新后端接口依赖**。若 Kimi 判断现有后端单队列 SSE 无法满足所需恢复体验，先报告并单列第二期方案，**不得**在第一期悄悄改为多订阅或许诺实时历史回放。

## 6. 最终验收与 Codex 核查清单

1. **路径缩短**：数据源详情点击一次能进入生成；运行成功不经第二个弹层即可评审；已有建议点击计数能直达。
2. **入口一致**：表详情默认仅当前表；数据源默认整库；切换后不把另一数据源建议/任务带过来。
3. **状态真实**：关闭 ≠ 取消；断线恢复展示持久状态而非伪实时；终态刷新建议；无建议、失败、取消都不显示虚假成功。
4. **决策安全**：建议未采纳不影响正式元数据；批量不包含隐藏/旧批次项目；编辑仅在受支持类型出现。
5. **并发与回归**：创建中不能双击提交；已有任务不重复开跑；错误响应与 SSE 断线不造成重复结束通知；旧数据源编辑/摄取、表详情编辑及查询页面不受影响。
6. **证据**：审查 Kimi 的实际 diff、类型检查、lint、生产构建和浏览器操作证据；缺真实后端/依赖时如实标注未验证，再决定是否需要修复或补测试。
