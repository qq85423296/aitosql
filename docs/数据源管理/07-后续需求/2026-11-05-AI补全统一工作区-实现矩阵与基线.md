| 既有后端约束（复核 `backend/app/api/ai_runs.py`、`store/ai_runs.py`、`store/suggestions.py`） | ① 同数据源 `queued/running` 互斥，重复创建 409 `E3101`；② SSE = 单进程单队列，断连即清队列，已结束任务仅回放 `run_end` 一帧——**不可重放**；③ 取消 = 协作式 `cancel` 端点；④ `accept` 逐条映射写目标表（comment→comment_custom / std_bind→field_standard_id / relation→relation confirmed / metric→metric_standard），全量成功才提交；⑤ `list` 按 id 倒序，`active_run` 取最新一条活动任务 |

**mock 与真实后端的语义差异（动工前记录，需随本任务收敛）**：

1. `mock.ts` 中 `run()` 的 `close()` 被模拟器当作「取消」（`isCancelled()` 直通）——与「关闭 ≠ 取消」原则冲突，需拆分「断流」与「显式取消」两个信号；
2. mock `GET /ai/completion-runs/{id}` 返回硬编码 done 行，与 `mockRunHistory` 实际状态脱节——轮询恢复路径在 mock 下会失真，需改为按 id 返回历史记录；
3. mock 创建不做 409 互斥——需补同数据源活动任务冲突检查（形状不变，仅补语义）。

## 2. 复用的既有 API（不改后端接口契约）

| 用途 | 接口 |
|---|---|
| 创建+跟随新任务（仅新建） | `aiRunsApi.run(body, {onStart,onLane,onEnd})`（mock/真实同形状） |
| 恢复/轮询/终态复核 | `aiRunsApi.list(dsId)` → `aiRunsApi.get(id)` |
| 显式取消 | `aiRunsApi.cancelRun(id)` |
| 建议查询（数据源/批次/表） | `suggestionsApi.list(dsId,'pending',{runId,table})` |
| 批量采纳（含 comment 编辑后采纳）/忽略 | `suggestionsApi.accept(ids, edits?)` / `ignore(ids)` |
| route.ai 预检 / 表清单 / 数据源清单 | `settingsApi.get` / `datasourcesApi.tables` / `datasourcesApi.list` |

轮询策略：运行中每 3s `get(id)` 作为地面真值（SSE 仅叠加泳道/日志）；终态停轮询并 `invalidateQueries(['suggestions',dsId])` + `(['aiRuns',dsId])`；`onEnd` 与轮询终态竞态由 `endedRef` 幂等收敛。

## 4. 第一期边界（不改后端）

- SSE 单队列不可重放是既有约束：重连后只展示持久状态轮询 + 明示延迟，不承诺实时历史回放；跨终端实时恢复属第二期另立任务。
- `metric` 建议仅在评审侧展示历史存量；生成配置不出现「生成指标」。
- 评审「本批建议」严格按 `run_id`；待评审总数按整个数据源；二者不混用。
