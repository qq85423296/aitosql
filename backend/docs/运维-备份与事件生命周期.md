# 运维手册：备份、恢复与事件生命周期（阶段 B3/E 落地）

> 适用版本：2026-10-31 修复轮。面向部署/运维者，不涉及 UI 操作。
> 本文只描述**已实现**行为；标注「待决策」的能力尚未实现，勿按已上线使用。

## 1. 数据库账号最小权限（部署基线，B3）

AItosql 的 SQL 安全由「R01-R15 AST 规则 + 写操作确认门 + ClickHouse readonly=1」构成，
**AST 校验不等价于数据库权限控制**（方言解析盲区、驱动差异、引擎侧函数都可能绕过应用层规则）。
部署者应按业务风险配置数据库账号最小权限：

| 数据源 | 应用层保护 | 部署侧要求 |
| --- | --- | --- |
| ClickHouse | 连接强制 `readonly=1`（D05，引擎级） | 仍建议使用只读账号 |
| MySQL / Doris | R15 硬阻断 + R06 写确认门（应用级） | **写 SQL 仅对有意启用的可信账号开放**；分析用途配只读账号 |
| PostgreSQL / Hive | 同上（应用级） | 同上 |

「只读账号模式、写账号分离、数据库资源组/扫描上限」属于产品策略增强，**待用户决策**，
本轮未实现（不在数据库连接层强制只读）。

## 2. 备份内容与安全属性

- 机制：每 4h（`BACKUP_INTERVAL_S`）+ API 立即备份，`VACUUM INTO` 产出 `app-{yyyyMMdd-HHmmss}.db`。
- 入备份：**仅 app.db 全量副本**（含 query/query_event/setting/datasource/语义/样例/记忆等全部表）。
- **排除项**：`checkpoints.db`（LangGraph 检查点）与 `exports/`（CSV 瞬态导出）**不入备份**。
- 密钥剥离：备份副本内 `provider.api_key_enc`、`datasource.password_enc` 一律写 `NULL`
  （恢复后需在设置页重新录入密钥）。
- 可选加密：`backup.encrypt=true` 时备份文件经 Fernet 加密（后缀 `.enc`）；
  密钥来源 `AITOSQL_FERNET_KEY` 或 OS keyring。**加密备份恢复前必须备好同一密钥**。
- 密级提示：即使剥离密钥密文，备份仍含**查询问题、SQL 字面量、结果预览、事件溯源明文**，
  属业务敏感数据；POSIX 下备份文件 0600，`backup.dir` 白名单限定在部署根内。
- 滚动保留：`backup.keep`（默认 10，**最小 1**——写入侧 422 校验，删除点二次钳制；
  keep≤0 的切片语义会反向删除最新备份，2026-10-31 修复轮已封堵）。

## 3. 恢复（离线运维操作，无 restore API）

恢复**不是** UI/API 操作，必须停服务离线执行：

1. **停服务**：终止 AItosql 进程（确认单实例锁 `.aitosql.lock` 已释放）。
2. **保全现场**：复制整个数据目录（`AITOSQL_DATA`，默认 `./data`）到安全位置——
   恢复失败可整体回滚。
3. **校验备份件**：确认备份文件完整（大小非零、时间为预期点）；
   `.enc` 加密备份先确认持有加密时同一 Fernet 密钥（`AITOSQL_FERNET_KEY` 或当时 keyring 条目）。
4. **解密（仅 .enc）**：用同密钥 Fernet 解密还原 `.db` 文件。
5. **替换**：将备份文件复制为数据目录下的 `app.db`（覆盖前先移走旧 `app.db`，勿直接删）。
6. **启动核查**：
   - `GET /api/health` 返回 `ok` 且 `missing_objects` 为空；
   - **进行中查询状态**：恢复后原 `running` 查询一律 `failed+标注`，
     **不适用 D03 自动续跑**（RESTORE_HINT 随 `GET /backup/list` 返回同一文案）；
   - 在设置页重新录入数据源密码与模型密钥（备份副本已置 NULL）。

## 4. 事件生命周期（query_event）

- **无自动保留策略**：query_event 按迁移定义没有 retention/TTL，仅随所属 query **级联删除**。
- 长期使用 app.db 会持续增大（事件 + 结果预览累积），属已知形态而非缺陷。
- 手动管理路径（现有能力）：删除会话/查询即经级联清理事件与预览；
  不要期待系统自动清理——**当前不存在自动 TTL**。
- 待决策（需单独设计，本轮未实现）：事件保留配置项、自动清理任务、
  结果永久归档、备份在线恢复端点（restore API/UI）。

## 5. 单实例运行契约（阶段 D，运维相关）

- 标准启动：`python scripts/dev.py`（持单实例锁 + 首启 token 打印 + 端口预检）。
- 直接 `uvicorn app.main:app` 仅供受控单进程开发/测试；应用 lifespan 会自行
  抢同一数据目录锁，**多 worker / 多进程同数据目录启动即明确失败**（拒绝静默多实例）。
- 限制：无法可靠探测所有外部进程管理器的部署形态；进程管理器自行 fork 的
  场景以「同一数据目录仅允许一个实例」为部署纪律，强制运行时检查列为后续项。
